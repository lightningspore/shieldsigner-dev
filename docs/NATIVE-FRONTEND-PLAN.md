# Native frontend implementation and acceptance plan

Implement the requested preview pipeline, camera/QR bridge and deferred startup imports one area at a time. Preserve existing signing/entropy behavior and the reviewed display/button map. Keep source, hardware and packaged-image evidence separate.

1. Build and test reusable Rust luma/RGB preview preparation against the current Pillow nearest-resize/expanded-rotation output. Preserve full-resolution decode/entropy/still APIs and GUI overlays.
2. Implement native socket frame reception, bounded latest-frame ownership and per-consumer pacing; move QR worker IPC behind PyO3 with exact binary results. Preserve managed-owner startup/stop, whole-frame deadlines, reconnect policy, cancellation, exit reporting and DMA cleanup. Keep existing behavior as an explicit comparison backend until the native path is qualified.
3. Remove unnecessary startup-route imports with exact pinned-source guards. Test every affected destination and measure import/ordinary startup memory.
4. Compare old/new ordinary app PSS/RSS/swap, allocations, CPU/frame/render/decode rates and interaction latency under the same image/hardware/configuration. Account for diagnostic overhead and native allocations outside tracemalloc.
5. Qualify integrated milestones on the board: Scan/Back/reopen, known public/binary QR data, camera seed generation, address/xpub/wallet navigation, error recovery and owner/DMA cleanup. Do not substitute direct-image decoding for optical capture.
6. Package the selected native path into a reproducible immutable image, verify the packed files/ABI/API, then flash and cold-boot test. Persisted source is not a deployed-image claim.
7. Update `UPSTREAM-DIVERGENCES.md`, evidence and runbooks throughout. Keep private captures and wallet data out of public records.

Initial checkpoint: clean source at `e25dc9b`; board has the reviewed 0.0.39-dev image plus temporary camera entropy/error-cleanup overlays and diagnostic input/capture. Those overlays must enter the next complete image. Existing quantitative evidence is in `MEMORY-THREADS.md` and `CAMERA-MEMORY.md`; it is a baseline, not a measurement of the new port.

Preview checkpoint: Rust resize/orthogonal rotation plus a reusable PyO3 PreviewRenderer passed 8 Rust tests and all 16 pinned-Pillow reference cases on the physical board. The ARM extension was built offline in an isolated output with the SDK cache mounted read-only. It is not yet selected by the app; native reception/integration is next.

QR transport checkpoint: persistent native worker IPC and PyO3 interface passed 16 Rust tests, host lifecycle/GIL tests, and three public byte-mode QR cases plus a blank frame using the actual ARM ZXing worker and packed ARM Python under QEMU. All 256 byte values were recovered exactly. The worker was reused and closed. This is not optical or on-board evidence; the app remains on its previous bridge while the user tests it. Frame reception and integrated cancellation remain unfinished.

Frame reception checkpoint: `firmware/lcd-rs/src/frontend_frame.rs` now parses and validates the camera header into a fixed three-slot Arc-backed pool. A held frame stays immutable; when every replacement slot is held, the incoming payload is drained through a 4 KiB scratch buffer and dropped. Independent consumer cursors apply latest-only pacing. A nonblocking poll reader checks cancellation at most every 20 ms and shares one header/body deadline. Host suite: 21 tests pass, including pinned-pool exhaustion/reuse, partial-frame rejection, independent consumers, stalled-read cancellation and trickling deadline. Native thread/condition-variable delivery, reconnect/owner integration and PyO3 frame interfaces still remain. Three full NV12 slots at 640×480 reserve 1,382,400 payload bytes; this must be measured in the integrated Mini app before accepting the memory tradeoff.

QR deadline follow-up: an intermittent Darwin socket timeout EINVAL was reproduced even with a valid manually constructed timeval. Replaced per-read socket timeout updates with nonblocking I/O plus deadline-aware poll. All host protocol/lifecycle tests pass after the change. The recorded ARM/QEMU QR result predates this change and is explicitly marked pending rebuild/retest; it does not qualify current source.

Receiver interface checkpoint: native `Receiver` owns a receiving thread, local three-slot pool, shared latest-frame/condition variable and eight bounded consumer cursors. Socket waits occur outside the delivery lock. PyO3 `FrameReceiver` duplicates the supplied connected socket fd with CLOEXEC, exposes native frames and releases the GIL for waits/close. Host suite now has 23 passing Rust tests. Compiled PyO3 fixture verifies independent readers, exact luma, frame lifetime beyond close, caller-fd preservation, idempotent cancellation and Python progress while waiting. `luma_bytes()` is a compatibility/export allocation, not the planned production zero-copy QR path. Managed connect/reconnect/ready acknowledgement and app integration still use the old implementation. The current Python wrapper serializes API calls with a mutex; reduce concurrent-read contention before integrated pacing measurements.

Direct-frame checkpoint: PyO3 `QrWorker.decode_frame()` and `PreviewRenderer.render_frame()` borrow the native NV12 Y slice directly, without constructing full-resolution Python bytes. The receiver wrapper now permits concurrent read/close operations, with the join handle separately synchronized. Host reference/lifecycle tests and 23 Rust tests pass. The updated corpus test sends actual socket frames through native reception, direct QR IPC and direct preview equivalence.

ARM compatibility issue found before deployment: the new thread-enabled uClibc extension builds but fails to import in packed Python with missing `getauxval`. Toolchain objdump confirms Rust thread/signal-stack code calls `getauxval(51)` (AT_MINSIGSTKSZ). The existing packed libc lacks that symbol. The new extension is not board-tested or selected. Resolve this ABI requirement and rerun the combined corpus before app deployment; do not treat the earlier QR-only ARM binary as qualification.

ARM compatibility resolved in candidate `96bb4c7…`: a uClibc-only link-time `--wrap=getauxval` adapter reads the kernel auxiliary vector without allocating. It does not interpose a generic getauxval symbol into Python. Packed ARM/QEMU checks match page size, HWCAP and minimum signal-stack entries against `/proc/self/auxv`, preserve errno on success and report ENOENT for an unknown key. The combined native receiver → borrowed-frame QR → preview test now passes all three public binary fixtures plus blank-frame handling, persistent worker reuse and closure. `reverse-engineering/rkaiq/frontend/receiver-arm-qemu-reference-2026-10-29.json` records current source hashes. These results do not qualify real camera/GUI operation.

Managed coordinator checkpoint: `shieldsigner_native_stream.NativeVideoStream` reuses guarded Python owner launch/ready acknowledgement/process logging/termination. The coordinator opens the socket, delegates frame reception/latest-frame pacing to Rust and reconnects only with a live managed owner, respecting the consecutive-failure budget and resetting it after complete frames. Protocol-invalid errors remain ValueError across PyO3 and are terminal rather than retryable. Two compiled-extension socket tests cover external reception/stop, managed EOF reconnect, and terminal malformed headers. This class is not yet selected by `shieldsigner_camera_compat`; camera GUI/QR adapters and configuration selection remain.

The receiver now preserves its I/O error kind across the native delivery state and Python boundary. This changes current runtime source after the receiver-02 ARM proof; rerun ARM qualification after the integration stabilizes.

App adapter checkpoint: `SHIELDSIGNER_FRONTEND_BACKEND=rust` (or launcher `--frontend-backend rust`) explicitly selects native reception/preview/QR. The default remains Python for comparison pending hardware qualification. Native NV12 decode reads return `NativeFrame`; the QR adapter borrows its Y slice. Preview uses Rust resize/expanded rotation once, then a small RGB Pillow image for GUI overlays. Full image/entropy reads retain RGB-shaped grayscale; true RGB still reads preserve all source pixels. The reviewed Camera hash gates the preview override. Native frontend requires an explicit QR executable. Existing non-native-image decoder fallback remains available for Pillow input.

Validation: all 54 Python tests pass with the compiled extension, including three new adapter tests for all preview rotations, entropy channel shape, exact RGB still pixels, direct binary QR transport/reuse/clean closure. Image staging includes both new adapters. The uClibc wrap link argument is now emitted by Cargo `build.rs` for Linux/uClibc, covering standalone and Buildroot package builds. Rebuild/retest ARM after these latest interface/error-kind changes, then qualify the actual GUI; no new native frontend has been installed on the user's board.
